## Design decisions

Keep DevelopmentRuntime, Supervisor, RunStore, Continuation, candidate verification and model response validation shared. Model descriptors choose Claude CLI, Codex CLI, command JSON or compatible HTTP independently of execution. Introduce an OS process/lifetime seam rather than cloning the loop for each OS. Preserve the Windows native executor and Job Object behavior. A portable trusted-local choice selects the host process backend; existing Windows-only descriptors remain compatible and never silently change on resume. Reject unavailable backends before paid planning.

POSIX trusted processes use a deliberately described process-group contract, with bounded pipes, cancellation, timeout, and ownership/recovery evidence. This is not a filesystem/network sandbox, credential isolation, or containment of malicious daemon escape. Do not claim stronger drainage or resume after uncertain ownership. Preserve the stricter Linux cgroup implementation as a separate admission-dependent facility. Native macOS evidence is an external gate if no Mac is available; simulated platform dispatch proves only dispatch.

Use standard Python packaging and console entry point. Prefer pipx installation of a built wheel (venv fallback), explicit upgrade/uninstall instructions, and no global runtime registration. New releases remain unauthorized. Keep profile-template for explicit advanced profiles and add a project-aware init that resolves PATH at setup time, selects safe tracked source paths via globs, freezes acceptance files and literal test argv, and supports exit-code checks as well as legacy exact output checks. No shell-string parsing. The generated profile is concrete and reviewable before a paid plan/start.

Offer normal local Git retention for ordinary third-party candidates, alongside explicit external retain-command integration. Respect existing Git hooks/policy and never fall back after a broker refusal. Built-in Git retention must bind the candidate, allowed paths, branch and clean post-commit tree, preserve identity/config where appropriate, refuse unexpected staged paths, and never push/merge. The enrolled development checkout itself always uses the existing host broker with no arguments and an exact-path request file.
